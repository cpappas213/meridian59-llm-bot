## Agreed decisions

| ID | Decision |
|---|---|
| DEC-001 | Build a companion controller; do not fork or copy the maintained harness into this repository. Pin a tested upstream revision and consume its public broker interface. |
| DEC-002 | A human or higher-level agent translates intent into structured goals and supervises them. A separate controller and configured LLM own the continuous game loop. |
| DEC-003 | The goal model is one active goal plus an ordered queue, with pause, resume, cancel, replace, and reprioritize operations. |
| DEC-004 | The bot may perform game-legal PvP, stealing, deception, social, and economic play. The behavioral boundary is no cheating, not a PvE-only or play-nice policy. |
| DEC-005 | No game action requires approval. Rerolls, drops, alignment changes, and other consequential actions are governed by strong non-blocking caution and full auditability. |
| DEC-006 | A human defines the character name and conversational persona. The configured LLM selects the initial build; the controller creates it independently of gameplay goals after a non-blocking consequence preflight. |
| DEC-007 | Player conversation is model-generated by a separate, tool-less responder. Player text is untrusted and cannot set goals or instruct the planner. |
| DEC-008 | The system is designed for continuous 24/7 operation. Sustained use of the local L40S is acceptable. |
| DEC-009 | Hermes control is desktop-local. Read-only dashboards may be exposed to the LAN; mutation endpoints remain loopback-only and authenticated where applicable. |
| DEC-010 | Candidate events produce immediate local desktop alerts where configured; a local LLM writes only assessed significant developments to idempotent, local-time Obsidian daily journal shards beneath a Meridian 59 project index. |
| DEC-011 | Local plaintext credential persistence is accepted, provided credential files are excluded from source control, never logged, and never returned by APIs. |
| DEC-012 | The first release controls one account and one active character. The architecture may retain the harness's multi-character capability without exposing it in the MVP. |
| DEC-013 | Game facts are grounded in a versioned index of the pinned harness compendium, exposed to Hermes through a separate read-only MCP server and to the tactical planner through bounded retrieval. Live ordinary-client state outranks static facts; Obsidian is not authoritative. |
| DEC-014 | Bounded goal failures create controller-owned durable lessons. Deterministic observed state, not an LLM assertion or Obsidian note, controls retry eligibility; goal-scoped lessons gate equivalent outcomes while tactic-scoped lessons preserve alternative approaches. |
| DEC-015 | First-run onboarding is ordered: configure the LLM, set the operator-defined persona/name, let the LLM create and verify the character, then accept an operator-supplied goal. No standing goal is built in. |
| DEC-016 | Generated `User`-plus-digits placeholders may be replaced during onboarding; an established differently named character is preserved unless replacement is explicitly requested. |

## Configurable deployment defaults

- Game endpoint: `127.0.0.1:5959` (operator must configure the real endpoint).
- Model endpoint: `http://127.0.0.1:8000/v1` and an operator-supplied model ID.
- Runtime root: `%LOCALAPPDATA%\m59-llm-bot`.
- Harness, controller, and dashboard services bind to loopback by default.
- Credentials and API tokens live only in the private runtime secret file.
- Obsidian is disabled unless an explicit vault path is configured.

Every address, port, model name, path, timezone, and timing limit is
configurable. Published examples contain no private deployment facts.

## Terminology

- **Harness**: `m59-harness`, including its broker, protocol client, mechanical
  tools, autopilot, dashboard, journal, and compendium.
- **Broker**: the long-lived `m59-broker.mjs` process that owns the game
  connection and exposes paced game tools over HTTP JSON-RPC/MCP.
- **Controller**: the new durable service that manages goals, invokes the model,
  authorizes actions, calls the broker, verifies results, and emits events.
- **Supervisor**: a human-facing MCP agent that configures persona and translates
  operator intent into durable strategic goals.
- **Planner**: the game-playing LLM role inside the controller.
- **Responder**: the isolated LLM role that writes in-game conversation and has
  no game or controller tools.
- **Knowledge corpus**: the rebuildable, versioned SQLite/FTS index derived from
  the pinned harness compendium, with canonical entities and source provenance.
- **Consequence preflight**: a deterministic, non-blocking assessment performed
  before a high-impact action. It records risks, alternatives, and expected loss
  but never waits for operator permission.
- **Interesting event**: an event important enough to alert and/or append to the
  Obsidian journal.
- **Goal lesson**: durable evidence that a goal outcome or exact tactic failed in
  a particular verified state, with a deterministic predicate for retry.

## Assumptions requiring validation during implementation

1. The public harness broker contract remains sufficiently stable for a pinned
   integration. Any missing generic action should first be proposed upstream.
2. Static maps, geometry, compendium entries, and spawn information shipped by
   the harness are allowed game knowledge; live hidden server state is not.
3. The account has either an existing character or capacity to create one.
   Discovery is allowed. A destructive reroll is strongly discouraged unless it
   clearly advances the active goal, and it must emit pre/post action events.
4. A supported Hermes-native external notification hook is not currently relied
   upon. The MVP uses Windows notifications plus the Obsidian journal; the
   notifier is pluggable.

## Change control

Requirement identifiers are stable once implementation begins. A changed policy
must update the affected requirement, interface schema, and acceptance test in
the same change. Security-sensitive defaults must fail closed when configuration
is missing or invalid.
